# Internationalization and Accessibility

[Feature index](../README.md) / [UI](README.md) / i18n and Accessibility

## 1. Internationalization

### 1.1 Structure

- vue-i18n in Composition API mode. One directory per language in `web/src/i18n/locales/` (`en/`
  first), with keys namespaced by screen and component (`test.start`, `result.grade.label`,
  `notices.slowLinkExtended.title`) and one JSON file per namespace, holding it as its top-level
  key. A notice's entry is named by its code in camelCase; an engine error's is its message key,
  `errors.<code>`, with the code as the engine sends it
  ([../architecture.md §4](../architecture.md#4-engine--ui-message-contract)).
- English is the source language and the fallback for missing keys. Other locales are lazy-loaded
  chunks.
- The engine never produces text: it emits codes (phase names, notice codes, error codes, plateau
  reasons, states), and the UI maps each code to a key. Every code in
  [../measurement.md §16](../measurement.md#16-confidence-and-notices) has a key.

### 1.2 Locale Detection

1. The `lang` URL parameter, if it names a supported locale.
2. The language stored in Settings, the `lang` field of `bitgauge.settings.v1`, when it names a
   supported locale.
3. The first supported entry of `navigator.languages`, matching the language subtag when the full
   tag is not available (`de-AT` → `de`).
4. English.

The `<html lang>` attribute follows the active locale.

### 1.3 Number, Unit and Date Formatting

- All numbers go through `Intl.NumberFormat` with the active locale (decimal separator, digit
  grouping); rates use three significant digits with their trailing zeros
  (`minimumSignificantDigits` and `maximumSignificantDigits` 3: 1.00 Mbit/s, 94.1 Mbit/s), except
  the round ends of the gauge's scale in its caption (1 Mbit/s – 10 Gbit/s); latencies the
  precision of [screens.md §6](screens.md#6-result-metrics-units-and-precision).
- Units are BitGauge's own decimal units (kbit/s, Mbit/s, Gbit/s; kB/s, MB/s, GB/s; kB, MB, GB;
  ms), translated as unit labels where a language writes them differently, with a non-breaking
  space between number and unit.
- Dates and times use `Intl.DateTimeFormat` with the active locale and the browser's time zone;
  relative times ("5 minutes ago") use `Intl.RelativeTimeFormat`.
- Exports (JSON, CSV) are locale-independent: ISO 8601 times and plain numbers.

### 1.4 Right-to-Left

RTL languages are **out of scope** for now. Layouts should use logical CSS properties where the
design export allows, so adding RTL later is not a rewrite.

### 1.5 String Rules

- No raw user-visible strings in templates; the ESLint vue-i18n plugin enforces it.
- Full sentences per key, with named placeholders (`{rate}`, `{seconds}`); never build sentences by
  concatenating fragments.
- Plurals use vue-i18n plural forms.
- The English locale is US English: license, color, behavior; "cancelled" keeps its double l, as
  the result format spells it.
- Technical tokens stay untranslated: HTTP/2, RPM, protocol names, notice codes in the result
  detail.
- The fixed label "HTTP loaded responsiveness — connection sharing not verifiable" is translated as
  a whole, keeping its meaning; translators must not shorten it to "RPM" alone.

## 2. Accessibility

Target: WCAG 2.2 AA for everything this specification controls.

### 2.1 Live Region for the Gauge

- The gauge's needle and arc are decorative (`aria-hidden`). Its numeric readout is the accessible
  value, but the readout itself is **not** a live region: it redraws several times a second.
- A separate, visually hidden polite live region announces the current phase on change and the
  rate at most every 5 s while running ("Download, 94.1 megabits per second"), not every 100 ms.
  The rate is the one the gauge shows: on upload, the sending progress, announced as such
  ("Upload sending, …").
- When a direction finishes, its headline is announced once ("Download result: 94.1 megabits per
  second"), from the headline its `finished` phase event carries, which is the result's number; a
  direction without a number is announced as finished without one. Announcements of one change
  are read as one message, the headline first, so the next phase does not cut it off.
- Spoken numbers have the scale and the digits of the visual ones, with the locale's long unit
  names (`Intl.NumberFormat` with `unitDisplay: 'long'`): "94.1 megabits per second", "51
  milliseconds"; a latency below the timer resolution is "less than" the resolution.

### 2.2 Reduced Motion

Under `prefers-reduced-motion: reduce`, the needle jumps instead of animating, chart updates are not
animated, and the countdown shows numbers without animation. Live data still updates.

### 2.3 Focus Order

- One logical order per screen following the visual reading order: navigation, server and
  connection info, Start/Stop, results, notices, details.
- A skip link ("Skip to main content") is the first focusable element of every screen: visually
  hidden until it has focus, it moves focus past the navigation to the screen's main content.
- When a run ends, focus stays on Stop/Start (now "Run again") and the result summary is announced
  (§2.7); focus is not moved unexpectedly.
- Dialogs (share, confirmations, compare) trap focus and return it to the invoking control on close.
- When the control that has focus goes away, focus moves to the control that takes its place,
  never to the page body: after a reset in Settings' changed list, to the next row's reset, else
  the previous row's, else the list's heading; after Reset all is confirmed, to the Settings
  heading; after Clear all is confirmed, to the empty state's Import JSON; after the auto-start
  countdown's Cancel, to Start.
- Visible focus indicators on every interactive element; styles from the design export must meet
  WCAG 2.2 focus appearance.

### 2.4 Keyboard

- Every action is reachable with the keyboard alone.
- **Start/Stop:** the button responds to Enter and Space and is the first control of the run
  area in focus order, after the server and connection info (§2.3). Escape (not a character key)
  stops a running test and cancels an auto-start countdown, from anywhere on the Test screen.
- **Page-wide Enter.** On the Test screen, Enter also starts a test (or starts it now during the
  countdown) when focus is on the page body or a non-interactive element. It does nothing when
  focus is on a link, button, input, select, textarea or any other interactive control (those keep
  their own Enter behavior), while a dialog is open, with a modifier key held, during IME
  composition, while Start is disabled, or while a test runs. Desktop layouts show the Enter and
  Escape hints on the button.
- There is deliberately no single-character shortcut, so nothing can start a test through speech
  input or a stray character key (WCAG 2.2 SC 2.1.4); Enter and Escape are not character keys.
- History rows are selectable with Space; Compare is reachable once two are selected.

### 2.5 Colour-Independent Grade Display

The bufferbloat grade is shown as the letter **and** words ("A+ Minimal bufferbloat", "F Severe
bufferbloat"); quality scores show their band names; notices carry an icon and text; chart series
differ in line style as well as color. No information is conveyed by color alone. In forced colors
(Windows High Contrast), where the browser replaces the export's colors, a selected or pressed
control (the header's theme switch, segmented controls, History's filter chips) keeps a border or
outline in a system color, and a legend's filled marker stays visible.

### 2.6 Contrast

Color contrast is delegated to the design export, which must meet WCAG 2.2 AA (4.5:1 for text, 3:1
for large text, UI components and chart lines against their background) in both light and dark
themes. Playwright runs axe checks on every screen ([../technical-stack/testing.md
§4](../technical-stack/testing.md#4-playwright-end-to-end)). Where the export misses it, this
section wins: the start button's key hint (`Enter`, `Esc`) is drawn at the button's full text
color, without the export's reduced opacity, which falls below 4.5:1 on the light theme's
primary button.

### 2.7 Screen Reader Result Summary

When a result is ready, a summary region reads, in order: status,
download and upload with qualifiers, idle latency and jitter, loaded-latency increase and grade,
HTTP loaded responsiveness with its label and state, quality scores, data used, and the notices.
This region is for screen readers only; Copy summary uses the narrower share-image content
([../security.md §7](../security.md#7-browser-only-history-and-privacy)).
Example: "Test complete. Download 94.1 megabits per second. Upload 38.2 megabits per second, low
confidence: unstable. Idle latency 51 milliseconds, jitter 1.9. Bufferbloat grade C, moderate
bufferbloat, plus 81 milliseconds under load. HTTP loaded responsiveness, connection sharing not
verifiable, over HTTP/2: download 412 round trips per minute, measured; upload 388 round trips
per minute, measured. Quality scores, an upper
bound since packet loss is not measured: streaming average, gaming bad, video calls poor. …"

The summary reads the HTTP loaded responsiveness per direction with its label, protocol and state
(a state other than `measured` in words, without a number when it has none) and each
quality-score experience with its band, or the inputs it is missing.
When the scores rest on one direction, the summary names their basis after "Quality scores", as
the design export's kit reads it: "Quality scores, download only, an upper bound since packet loss
is not measured: …".
A Continuous result reads its one direction with its run-wide minimum and maximum and its "p90,
last hour", and the other direction as not run.

Download and upload carry their qualifiers (partial, low confidence with its reasons, or limited
by the device's CPU; insufficient data, skipped or failed instead of a number), and the notices are
read by title. A direction or idle latency the run's settings left out is not mentioned. The summary
is emptied when the next run starts.

Charts have a text alternative: each Result-detail chart has a Chart or table toggle, and the table
holds the per-window statistics of [screens.md §2](screens.md#2-result-detail--resultid).

### 2.8 Headings

Every screen has exactly one `h1`, its title, so a screen reader's heading list starts from it;
sections below it use `h2` and down, without skipping a level. The Test screen's `h1`,
"Speed test", is visually hidden: the gauge and Start are what the screen shows first, and a
visible title would push them down.

### 2.9 Target Size

On phones every control is at least 24 × 24 px (WCAG 2.2 SC 2.5.8), counting the label of a
checkbox or radio that a click on the label toggles as its target; a link inside a sentence is
exempt, as the criterion allows. The
primary actions are at least 44 px high: Start, the actions and close buttons of dialogs, the tab
bar's items and History's result cards.
