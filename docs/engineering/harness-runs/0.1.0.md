# v0.1.0

**v0.1.0 shipped on the accuracy harness's CI tier alone.** By the maintainer's decision on
2026-11-09, the manual tiers this file normally records (the floor and ceiling tiers, the real
Android Chrome and iOS Safari runs over a VPN, the real Safari checks and the Continuous memory
check) were **not run** for this release, and the CI tier's failures below were **not** re-run
before it was tagged ([release run
42689009091](https://github.com/leinardi/bitgauge/actions/runs/42689009091),
`v0.1.0` on `c50c573`). It is the one exception to
[release.md step 1](../../release.md#how-to-release); the next release is compared with this
file as it stands.

## CI Tier

Two runs of `harness.yaml`, both on GitHub's `ubuntu-latest` runners:

- [42646806972](https://github.com/leinardi/bitgauge/actions/runs/42646806972), on `7d1958f`: all
  21 runs pass.
- [42680553230](https://github.com/leinardi/bitgauge/actions/runs/42680553230), on `c50c573`, the
  released commit: 18 pass, **3 fail**. Between the two commits the only change to the web app is
  a vue-i18n bump (`c64f5c1`); the rest is CI, tests and docs.

Every rate of both runs is within its tolerance. The three failures are each one direction's loaded
latency against the concurrent ICMP ping, outside ±20 % or 5 ms, whichever is larger:

| Profile | Browser | Direction | BitGauge loaded | Ping | Rates |
| --- | --- | --- | --- | --- | --- |
| `ci-500k-300ms` | firefox | download | +19.0 ms | +13.5 ms | −1.5 % / −3.7 % (±15 %) |
| `ci-500k-300ms` | webkit | upload | +17.0 ms | +11.0 ms | −2.0 % / −3.3 % (±15 %) |
| `ci-1g` | firefox | download | +8.0 ms | +0.2 ms | −1.6 % / +0.0 % (±10 %) |

Not investigated before the release. The same profiles passed on `7d1958f` with readings close to
these (`ci-500k-300ms` firefox and webkit at +17.0 ms), so they sit near the edge of the tolerance
on these runners; whether that is runner noise or a real spread is open.

#### Environmental limits

- tc shaping jitter (tbf burst sizes, netem timer granularity).
- Docker bridge overhead at high rates.
- Playwright WebKit ≠ Safari: Worker XHR and nextHopProtocol behavior must be re-checked on real
  Safari.
- Mobile power management: device runs happen with the screen on.

What the harness cannot prove: real Wi-Fi behavior, real VPN MTU effects, carrier-grade NAT, and
anything about networks the project does not target.
